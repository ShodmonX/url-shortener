Overview

Short links, ownership, and analytics in one API.

URL Shortener API that allows users to generate short links, track analytics, manage personal URLs, and create anonymous links that still redirect normally.

What it does

Create collision-safe short URLs, attach them to authenticated users when needed, and collect click analytics without putting write pressure on the redirect path.

How it is used

Register or log in for ownership features, or call the create-link endpoint anonymously for one-off short links managed by a returned manage token.

Quick Start

Go from account creation to analytics in six steps.

These examples use the API prefix __API_PREFIX__ and the configured public base URL __PUBLIC_BASE_URL__.

1

Register a user

Create an account and receive both access and refresh tokens.

curl -X POST __PUBLIC_BASE_URL____API_PREFIX__/auth/register \
  -H "Content-Type: application/json" \
  -d '{
    "email": "alice@example.com",
    "password": "StrongPass123!"
  }'
2

Log in

Use the login endpoint when you need a fresh token pair for an existing user.

curl -X POST __PUBLIC_BASE_URL____API_PREFIX__/auth/login \
  -H "Content-Type: application/json" \
  -d '{
    "email": "alice@example.com",
    "password": "StrongPass123!"
  }'
3

Store the access token

Send it on protected endpoints with the standard bearer header.

Authorization: Bearer ACCESS_TOKEN
4

Create a short URL

The same endpoint works for both anonymous and authenticated clients. If a bearer token is present, the new URL is owned by that user. 

curl -X POST __PUBLIC_BASE_URL____API_PREFIX__/links \
  -H "Authorization: Bearer ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://example.com/pricing",
    "custom_alias": "pricing-2026"
  }'
5

Redirect with the short code

Resolve the code directly from the root path.

curl -i __PUBLIC_BASE_URL__/pricing-2026
6

Fetch statistics

Owned URLs expose richer stats through the user-scoped stats endpoint.

curl __PUBLIC_BASE_URL____API_PREFIX__/urls/URL_ID/stats?days=30 \
  -H "Authorization: Bearer ACCESS_TOKEN"

Authentication

JWT access and refresh tokens, plus manage tokens for link-level operations.

Access token

Short-lived JWT used for authenticated endpoints such as /users/me, /users/me/urls, and /urls/{id}/stats.

Authorization: Bearer ACCESS_TOKEN

Refresh token

Long-lived JWT stored in an HttpOnly cookie by default and rotated through POST __API_PREFIX__/auth/refresh. JSON body fallback is still accepted for transitional clients.

Manage token

Returned when a link is created. It is sent as X-Manage-Token for manage-token endpoints like preview, QR retrieval, and analytics by short code.

X-Manage-Token: MANAGE_TOKEN 
curl -X POST __PUBLIC_BASE_URL____API_PREFIX__/auth/refresh \
  -H "Cookie: refresh_token=REFRESH_TOKEN"

Link creation and manage-token flows

GET __API_PREFIX__/links/alias-availability

Check whether a custom alias can be used before creating a short link. The same validation rules as link creation are applied. 

curl "__PUBLIC_BASE_URL____API_PREFIX__/links/alias-availability?alias=pricing-2026"
{
  "alias": "pricing-2026",
  "available": true,
  "reason": null
}

Anonymous vs Authenticated URLs

Ownership is optional and determined by whether a bearer token is present.

Anonymous client

  • Can create short URLs through POST __API_PREFIX__/links.
  • Saved with user_id = null.
  • Redirects work exactly the same as owned links.
  • Does not appear in any user's /users/me/urls response.
  • Can still be managed with the returned X-Manage-Token.

Authenticated client

  • Creates the same way, but includes Authorization: Bearer ....
  • The new link is attached to the current user.
  • It appears in GET __API_PREFIX__/users/me/urls.
  • Owner-only statistics are available at GET __API_PREFIX__/urls/{id}/stats.
  • Non-owners do not get visibility into another user's URL stats.
